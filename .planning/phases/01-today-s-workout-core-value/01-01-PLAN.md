## Phase Goal

**As a** gym beginner, **I want to** open the installed app offline, see today's workout, log each set in seconds and be told what load to use next, **so that** I always know what to do and my loads progress automatically.

This plan is the Walking Skeleton tracer (see `SKELETON.md` in this phase folder): the thinnest real path through every layer of the app, proven in headless Chrome.

## Scope note

14 files (checker warning band 10–14), on purpose: a no-build tracer needs one file per layer (page shell, router, render helper, storage, program data, exercise data, three pure domain modules, one action module, two screens, the E2E runner and its scenario). Each file is small (about 20 to 150 lines). The visual vocabulary, install metadata and service worker live in the parallel plan 01-02, and finish, onboarding, Settings and publishing live in 01-03, so this plan stays near 70k tokens.

<objective>
Build the core path end to end: Today shows the next workout (Treino A on a fresh install) → one tap starts it → each set is saved to IndexedDB on tap → a reload resumes the workout. Every change to the in-progress workout runs through one promise queue, so fast double taps never lose a set. The user can step between exercises, and Today offers "Continuar treino" while a workout is open.

Purpose: proves the architecture (vanilla ES modules, raw IndexedDB write-through draft, hash routing, the planExercise contract) before any feature is layered on, and gives every later plan a zero-dependency E2E runner.
Output: index.html, the router, the render helper, the data layer, the program and exercise data, the dates/history/plan domain, serialized workout actions, the Today and Workout screens, tools/smoke.mjs and the 01-core-loop scenario.
</objective>

7. src/domain/history.js (pure, never reads the clock): nextTemplate(sessionsDesc, rotation = ['A','B']) finds the most recent session with complete === true and returns the letter after its templateId in rotation (wrapping). 9. src/actions/workout.js (IndexedDB is the only source of truth; actions never keep a draft copy in memory between calls):
- queue(task): keep one module-level promise chain. Append the task with chain.then(task), store the new tail as the chain with its rejection swallowed (so one failed task never blocks later ones), and return the un-swallowed promise so the caller still sees the result or the error.
- mutate(fn): queue(async () => { read getActive(); when it is null return null; next = fn(draft) (fn changes the draft and returns it); await putActive(next); return next }).
- startWorkout(templateId, now): runs inside queue(). It loads listSessions(), getAll('exercisePrefs') and EXERCISES, calls planExercise per program item with history = exerciseHistory(sessions, id), incrementKg from the prefs row when present, and today = localDate(now), and builds the draft: entries carry exerciseId, plannedSets = plan.sets, repMin, repMax, restSec, load = plan.load, reps = plan.targetReps, feel null and sets []. Also startedAt = now, localDate, currentIdx 0, restEndsAt null. It awaits putActive and returns the draft.
- logSet(entryIdx, now): mutate() that appends {load: entry.load, reps: entry.reps, kind:'work', at: now} to that entry. The set is on disk before the UI shows it (TREINO-07), and because it runs inside the queue a second tap reads the draft the first tap already wrote.
